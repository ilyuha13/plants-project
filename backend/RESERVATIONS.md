# Бронирования MVP

## Готовый этап

- Обычная корзина автоматически удерживает растения на час.
- Авторизованный клиент отправляет один запрос с именем, способом связи и комментарием.
  Можно создать запрос для пустой корзины. Клиент не передаёт идентификатор чужой корзины.
- С момента запроса растения удерживаются до ручного решения администратора.
  Повторный запрос отклоняется и не сбрасывает дату первого обращения.
- Администратор подтверждает срок или бессрочную бронь, сумму фактически полученной
  предоплаты (включая 0), дату напоминания и внутренний комментарий.
- Состав можно менять. Новые растения получают действующий режим корзины;
  удалённые возвращаются в продажу. Условия, напоминания и предоплата сохраняются.
- Срок подтверждённой брони не освобождает растения. Срок и напоминание добавляют
  бронь в «Требуют внимания». Списки и счётчик админки обновляются каждую минуту.
- Отдельного автоматического сообщения клиенту нет: администратор связывается вручную.
- Освобождение очищает состав и возвращает доступные растения в продажу, сохраняя
  контакты, комментарии и записанную предоплату. При ненулевой сумме нужно отдельное
  подтверждение. Это не операция возврата денег: сумма остаётся видимой клиенту и
  администратору, расчёты урегулируются отдельно. Полноценный журнал платежей — следующий этап.
- Внутренний комментарий не возвращается клиентским getCart.

## Совместимость данных

В этом этапе сохранены прежние значения enum в БД:

| Значение | Значение в продукте |
| --- | --- |
| AUTOMATIC | Часовая корзина |
| RESERVED_PREPAID_REQUEST | Единый запрос бронирования |
| RESERVED_PREPAID_CONFIRMED | Подтверждённая бронь, в том числе с 0 ₽ |

Старые RESERVED_NO_PREPAID мигрируют в подтверждённые брони с 0 ₽.
Старым подтверждённым броням reviewAt заполняется из reservedUntil.
У старых запросов снимается автоматическое окончание. Контакты, которые раньше
передавались только в Telegram, восстановить из БД нельзя: они отмечены в админке
как отсутствующие. Старые четыре обработчика заменены едиными действиями.

Миграция добавляет поля в Cart и индекс, не удаляя заказы и позиции.
Переключение на старый код после миграции небезопасно по бизнес-правилам:
прежний cron освобождал подтверждённые брони по сроку.

## Следующий этап

Преобразование заявки на покупку в оплаченный заказ администратором,
фиксированный состав и цены заказа, доставка, статусы и возврат денег.
Текущий checkout пока остаётся прежним клиентским оформлением: переход на
создание оплаченного заказа только администратором ещё не выполнен.
Товарные предложения с количеством и гостевая корзина также отдельные этапы.

## Ручная проверка

1. Клиент добавляет экземпляр, отправляет запрос с контактами.
2. В корзине отображается удержание до решения, в админке — новый запрос.
3. Администратор подтверждает «Сутки бесплатно»: 0 ₽, срок и напоминание через сутки.
4. Клиент добавляет и удаляет растения, включая удаление всех. Условия сохраняются.
5. Администратор меняет условия на бессрочную бронь с предоплатой и напоминанием.
6. Переплата при уменьшении состава видна; деньги автоматически не возвращаются.
7. Администратор освобождает бронь: растения доступны, записанная предоплата сохраняется.
8. В тестах подтверждается, что прошедший срок не освобождает подтверждённую бронь.

Перед ручной проверкой после миграции перезапустите backend, чтобы он загрузил
новый Prisma Client. Исходники frontend обновляются через Vite.
