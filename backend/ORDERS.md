# Заявка на покупку → оплаченный заказ

## Процесс

1. Клиент нажимает «Оформить покупку», указывает имя, хотя бы один способ связи
   (телефон или мессенджер) и пожелания по доставке.
2. Checkout сохраняет заявку в корзине. Не создаёт Order, не переводит растения
   в SOLD и не очищает состав. Растения удерживаются до решения администратора.
   У подтверждённой брони сохраняются срок, напоминание и предоплата.
3. В разделе «Бронирования» заявка помечается отдельно, доступен фильтр покупок.
   Администратор согласовывает окончательные состав, цены, получение и оплату.
4. «Создать оплаченный заказ» открывает итоговую форму. Цена каждой позиции
   редактируется, стоимость доставки включается в итоговую сумму.
   Полученная сумма — вся фактическая оплата, включая уже внесённую предоплату.
5. Сервер проверяет полномочия администратора, актуальность корзины, точный состав,
   оплату и доступность каждого растения. Создание защищено транзакцией и блокировкой
   корзины, повторное подтверждение не создаёт второй заказ.
6. В одной транзакции создаётся COLLECTING, фиксируются позиции, суммы и доставка,
   растения получают SOLD, а корзина и её условия очищаются.
7. Администратор переходит в карточку заказа. Клиент видит последние 10 своих
   заказов в корзине и может открыть их. Доступ к чужим заказам закрыт.

## Что сохраняется

Order: контакты, доставка (самовывоз, по городу, 5Post, СДЭК, Почта, Ozon), адрес, ПВЗ, стоимость и
комментарий к доставке, итоговая сумма, всего получено, ранее внесённая предоплата,
идентификатор исходной корзины и комментарий клиента.

OrderItem: связь с физическим экземпляром плюс снимки названия, инвентарного номера,
согласованной цены и ссылок на фото. Последующее изменение карточки растения
не меняет эти значения в заказе. Сами файлы фотографий не копируются.

Деньги рассчитываются через Decimal. Переплата сохраняется и показывается отдельно.
Администратор подтверждает фактическую оплату вручную; интеграции с банком нет.
При изменении корзины с момента открытия итоговой формы создание отклоняется:
нужно открыть форму заново и проверить обновлённые данные.

## Старые данные и ограничения

Миграция только добавляет поля. Старым заказам не приписываются вымышленные суммы
оплаты и исторические цены. Их карточка помечена как старая и показывает доступные
текущие данные для позиций без снимков. Все прежние связи и статусы остаются.

Упаковка, отправка и завершение реализованы (см. ниже). Отмена с возвратом
денег и отдельным выбором освобождаемых растений — следующий этап.
Старый cancelOrder отклоняет новые оплаченные заказы, чтобы не освободить их
растения автоматически без учёта возврата. Для старых заказов прежний механизм сохранён.

Корзину по-прежнему можно менять до создания заказа, даже после заявки на покупку.
Условия брони при этом сохраняются. Предоплата при освобождении брони пока остаётся
записанной до отдельного урегулирования; автоматического возврата нет.

## Проверка на сайте

1. Клиент добавляет растения и отправляет заявку на покупку с доставкой.
   Корзина остаётся заполненной, заказ ещё не создан.
2. В админке открывается «Заявки на покупку», затем «Создать оплаченный заказ».
3. Проверяется цена каждой позиции, способ получения и доставка. Неполной оплаты
   недостаточно для создания. Всего получено вводится с учётом предоплаты.
4. После подтверждения появляется один заказ «Сборка», корзина очищается.
5. Карточка заказа сохраняет согласованные цены, оплату, ПВЗ/адрес и доставку.
6. Клиент открывает заказ из раздела «Мои заказы» в корзине.
7. Если состав изменён в другом окне, устаревшая итоговая форма не создаёт заказ.

После применения миграции перезапустите backend для загрузки нового Prisma Client.

Инвентарный номер доступен только администратору. Для клиента он исключён
из API заказа (снимка и текущего экземпляра), корзины и каталога.
Фотографии в заказе увеличены и открываются по нажатию в отдельном окне.

## Способы получения

- Самовывоз: адрес клиента не требуется.
- Доставка по городу: обязателен адрес доставки.
- 5Post, СДЭК и Ozon: обязателен адрес ПВЗ, номер пункта можно дописать там же.
- Почта: обязателен почтовый адрес; поле подсказывает указать индекс.

Клиент может отложить выбор до общения с администратором. Для создания
оплаченного заказа конкретный способ обязателен. Ненужное поле адреса скрывается
в форме и не переносится в заказ, даже если осталось от предыдущего выбора.
Прежние значения PVZ/ADDRESS/OTHER сохранены для старых записей и подписаны
как неуточнённые; при новом оформлении администратор выбирает службу явно.

Для Почты, Ozon, СДЭК и 5Post обязательны ФИО и отдельный телефон получателя
как в заявке клиента, так и при создании заказа администратором. Фамилия и имя
обязательны, отчество — при наличии. Телефон допускает обычное форматирование
(плюс, пробелы, скобки, дефисы), должен содержать 10–15 цифр; мессенджер
не заменяет телефон. Для самовывоза и доставки по городу прежние требования сохранены.

## Обработка заказа

Администратор проводит оплаченный заказ через COLLECTING → PACKED → SHIPPED
→ DELIVERED. Для самовывоза можно завершить из COLLECTING или PACKED, без отправки.
Переходы назад, пропуск упаковки при доставке и повторное подтверждение запрещены.
Сервер сверяет ожидаемый статус и обновляет его условно: два одновременных
подтверждения не перезаписывают дату действия. Растения остаются SOLD.

Для Почты/Ozon/СДЭК/5Post при отправке обязателен трек-номер, для городской
доставки он необязателен. Даты упаковки, отправки и завершения сохраняются
по времени подтверждения на сервере и показываются владельцу и администратору.
Трек можно выделить и скопировать в карточке. Автоматического отслеживания нет.

В админке есть очередь «В работе» (сборка, упаковка, отправка) и фильтры по
каждому статусу и по всем заказам, включая старые. В рабочей очереди сначала
старые заказы, в остальных списках — новые. Карточка и очередь обновляются
раз в минуту. Неоплаченные старые заказы нельзя провести по новому процессу
без отдельного разбора; их данные не считаются автоматически оплаченными.

Ручная проверка: новый оплаченный заказ → упаковка → отправка с треком
→ завершение. Убедитесь, что клиент видит статус, даты и трек, но не кнопки.
Отдельно проверьте самовывоз: завершение из сборки без трека и даты отправки.
Завершённый заказ уходит из «В работе», оставаясь в фильтре «Завершён» и «Все».
Для этого этапа нужна миграция 20261026110000_order_processing.
